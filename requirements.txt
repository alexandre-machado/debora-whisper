# Core - OpenVINO inference
# Upper bound excludes the 2026.x line: optimum-intel 2.0.0 hard-requires
# openvino>=2026.0, and OpenVINO's Whisper-on-NPU export/compile behavior has
# moved across recent releases (see PR description) with an open unresolved
# NPU compile report against 2026.x. Stay on the already-working 2025.x line
# until someone validates 2026.x on real NPU hardware.
openvino>=2025.1,<2026.0
openvino-genai>=2025.1,<2026.0

# Model export
# This cap does NOT by itself keep resolution off optimum-intel 2.0.0 /
# openvino 2026.x: optimum's own "openvino" extra has no upper bound on
# optimum-intel, and optimum-intel's own "openvino" extra has no upper bound
# on openvino (verified by resolving `optimum[openvino]>=1.23.0,<2.0.0` in
# isolation - it picks openvino==2026.2.1 + optimum-intel==1.25.2). The thing
# that actually forces the optimum-intel 1.x line is the direct
# `openvino>=2025.1,<2026.0` pin above, which conflicts with optimum-intel
# 2.0.0's unconditional `openvino>=2026.0` requirement and makes the resolver
# backtrack. Do not drop the openvino cap above as "redundant" with this one;
# it is the load-bearing constraint.
optimum[openvino]>=1.23.0,<2.0.0
# Upper bound matches optimum-intel 1.25.2's own declared window
# (transformers<4.54,>=4.36). The originally-reported "transformers>=4.53
# breaks Whisper export" claim did NOT reproduce here: transformers==4.53.0 +
# optimum-intel==1.25.2 + openvino==2025.2.0 successfully exported
# openai/whisper-tiny.en via `optimum-cli export openvino` in this
# verification (see PR description). Bound kept at <4.54 anyway to match the
# tightest constraint optimum-intel itself declares for this line.
transformers>=4.36,<4.54
# torch is a transitive dependency of optimum (unpinned upstream) but a
# fresh install of the pins above still resolves torch==2.13.0, which breaks
# optimum's ONNX exporter (`ImportError: cannot import name '_attention_scale'
# from torch.onnx.symbolic_opset14`). The successful `optimum-cli export
# openvino` run this PR reports used torch==2.4.1. Cap below the break so a
# fresh install of the export path actually works; not used by the shipped
# app at runtime (models arrive pre-exported via snapshot_download).
torch>=2.0,<2.5

# Parakeet TDT preprocessing
onnxruntime>=1.18.1,<2.0.0
