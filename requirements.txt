# Model export
# The optimum cap does NOT by itself keep resolution off optimum-intel 2.x:
# optimum's own "openvino" extra has no upper bound on optimum-intel. That
# used to be enforced indirectly by the old openvino<2026 cap (optimum-intel
# 2.0.0 hard-requires openvino>=2026.0); with openvino on 2026 that conflict
# is gone, so optimum-intel is now capped directly. 1.25.2 + openvino 2026.4.1
# passes `pip check`. Moving to optimum-intel 2.x changes the transformers
# window too and is a separate migration.
optimum[openvino]>=1.23.0,<2.0.0
optimum-intel>=1.25,<2.0
# Upper bound matches optimum-intel 1.25.2's own declared window
# (transformers<4.54,>=4.36). The originally-reported "transformers>=4.53
# breaks Whisper export" claim did NOT reproduce here: transformers==4.53.0 +
# optimum-intel==1.25.2 + openvino==2025.2.0 successfully exported
# openai/whisper-tiny.en via `optimum-cli export openvino` in this
# verification (see PR description). Bound kept at <4.54 anyway to match the
# tightest constraint optimum-intel itself declares for this line.
transformers>=4.36,<4.54
# torch is a transitive dependency of optimum (unpinned upstream). It is
# floored, not capped, on security grounds: torch <2.6.0 is vulnerable to
# CVE-2025-32434 (critical, 9.8, RCE via torch.load even with
# weights_only=True) and torch <2.10.0 is vulnerable to CVE-2026-24747
# (high, 8.8, RCE via a corrupted-pickle bypass of the same weights_only
# guard) -- both hit exactly the checkpoint-loading path that
# `optimum-cli export openvino --model <name>` exercises against
# arbitrary, possibly-untrusted HuggingFace repos. >=2.10 is the first
# version patched against both.
#
# Known trade-off, deliberately accepted: optimum's ONNX exporter is
# broken on every torch>=2.10 currently on PyPI (checked the full
# [2.10.0, 2.13.0] range) because `optimum/exporters/onnx/model_patcher.py`
# imports `_attention_scale` from `torch.onnx.symbolic_opset14`, and that
# symbol was removed from torch before 2.10.0. So `optimum-cli export
# openvino` will fail with
# `ImportError: cannot import name '_attention_scale' from
# torch.onnx.symbolic_opset14` until optimum ships a fix upstream. This is
# accepted because torch is never imported by the shipped app (models
# arrive pre-exported via snapshot_download) -- only someone manually
# running a custom export hits this, and shipping every user a torch with
# a critical RCE to keep that optional path working is the wrong trade.
# Do not lower this floor to "fix" the exporter without re-opening both
# CVEs.
torch>=2.10
